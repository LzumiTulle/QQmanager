# 桌面应用

## 日常使用

1. 双击 QQmanager。首次启动自动运行本机服务并打开应用窗口。
2. 在“关注与设置”配置并测试模型；在“自动接入”完成 QQ 插件配对或选择资料监听目录。
3. 平时正常使用 QQ；在 QQmanager 查看重要信息、原始记录、文件与待办。
4. 关闭窗口后后台继续运行。菜单栏 / 托盘图标可重新打开窗口，或选择“退出 QQmanager”。

插件 0.1.5 会自动保存所选群的图片和文件（单个不超过 20 MB）。信息详情可查看原图、阅读 Word 等文件的提取正文，并下载原文件；“文件”页可搜索文件名与正文。图片文字在本机识别，提取文字交给已启用的模型分析。考试表格的行列、日期和班级需对照原图确认，再创建提醒。

旧版只保存附件占位文字的记录，可点击“重新获取附件”尝试补取。仅匹配当前所选群中已有记录的附件，受 QQ 最近消息范围、缓存和服务器有效期限制，不保证恢复全部历史；识别失败时原文件仍可查看、下载与重试。语音、视频暂不识别。

Windows 图片识别依赖系统已安装的 OCR 语言，优先使用简体中文。英文系统需要通过 Windows 设置安装中文 OCR 语言包才能识别中文，程序不自动修改系统语言或执行策略。参见 [Microsoft OCR 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)。

Mac 日常入口是“应用程序 → QQmanager”，可以将应用拖到 Dock，之后点击图标打开。安装助手可从 QQmanager 菜单中的“安装 / 更新 QQ 消息插件”打开，无需再去项目目录寻找，也无需每次选择 QQ 的 Documents 目录。

首次使用可先在“账号与备用添加方式”绑定 QQ 账号，完成插件安装后再选择群，无需预先填入群号。

在“接入 → QQ 插件”查看 QQ 同步的群列表，按群名或群号搜索并勾选，然后点击“保存群聊选择”。取消勾选或点击“移除”可停止收集，约 10 秒内生效；取消全部并保存会暂停收集。已有消息、分析与待办保留。完整列表需要 QQ 插件 0.1.5；老版本可在 Windows 的「设置 → 桌面应用」或 Mac 的应用菜单中更新插件，再重启一次 QQ。群列表仅存本机，不会自动勾选新群，也不会将未选群消息发送给模型。账号详情里保留按群号添加的备用方式。

登录系统后后台启动默认开启，可在 Windows 的「设置 → 桌面应用」或 Mac 的应用菜单中关闭。开机启动指**当前用户登录系统后**，不在未登录时运行，不自动登录 QQ。第一次将 Mac 应用从 DMG 拖入“应用程序”后再打开；不要长期从 DMG 或临时解压目录启动。

概览提供今天、本周、本月切换，大数字汇总待办、收集消息和筛选出的重要消息；按日期展示待办、考试、调课和通知，普通课程仅在课表页展示。消息按入库时间统计，可翻页查看全部原文，不受历史列表 500 条上限影响。课表按时间轴对齐，空课留白。“事项”页按考试、学业、通知等分类，每类预览 3 项。考试按同群、同学期、同一周合并；后续通知、图片和文件放进原事项，收到新消息后标记“有更新”。详情保留最新补充、附件、逐条原文和变更记录；可手动合并、拆开、收藏、已读或添加待办。其他事项使用本地规则与已启用模型整理，只发送授权群的事项标题，不跨群自动合并。群聊、搜索、阅读状态可以组合筛选，群选择会记住。

## 个人课表与校历

在“课表”页先设置一个已知日期对应的教学周，以及学期总周数；按周一开始计算，用户设置优先于导入文件。可修改五个大节的上课时间。主页和课表页均可切换上一周、下一周或回到今天。

“导入课表 / 导入校历”支持 PNG/JPEG/WebP、XLS/XLSX、CSV/TXT、PDF/DOCX（扫描 PDF 请改用图片）。图片在本机 OCR，表格保留行列信息；确认允许发送识别文字后，用已配置模型整理成预览，点击保存才加入课表。课表与校历独立导入，导入课程不会覆盖已设周数。模型识别可能有错，尤其模糊图片和合并单元格，请核对预览；Windows 中文图片需系统安装中文 OCR 语言支持。

课程默认全部启用，个人选修课自行添加。支持星期、节次、单双周或离散周次、教室、教师修改与停用。重复导入相同记录不会重复添加或覆盖手动修改；新文件中有变化的记录会作为新安排，需停用旧安排。重叠课程会提示核对。没有明确上课时间的课程放在待安排区；移除后可立即撤销。

日历中的事项标记与课表独立：明确日期显示在当天（自动识别日期标为待核对），只有周次的事项显示在本周事项栏。日程与校历有冲突会提示，不自动改写个人课表或覆盖已确认的提醒。

## 数据与旧版兼容

新安装默认使用兼容旧版的用户数据目录下的 `data`（Mac 通常为 `~/Library/Application Support/QQmanager/data`，Windows 为 `%APPDATA%/QQmanager/data`）。Windows 可从「设置 → 桌面应用 → 打开数据文件夹」查看实际位置，Mac 可从应用菜单打开。

已有兼容 QQmanager 服务占用 8765 时，桌面版核对健康协议并复用它，记住其数据目录，不复制或重置聊天、群选择或密钥。退出桌面版不会停止外部旧服务。若要迁移到完全由桌面版管理，先确认应用已识别原数据目录，再停用旧 LaunchAgent；下次打开桌面版会使用原目录启动内置服务。

应用自建的服务随应用退出；应用异常结束后，通过管道 EOF 停止子进程，减少残留服务占用端口。服务启动失败会显示错误，不自动更换端口造成 QQ 插件断连。端口固定为 127.0.0.1:8765。

原文、文件、模型 Key 及插件配对凭据均属于本机私有数据。当前数据库中的模型 Key 依赖操作系统用户权限保护，尚未迁移至系统凭据保险库。

## QQ 插件

Mac 菜单提供“安装 / 更新 QQ 消息插件”，打开随包附带的原生助手。QQ 必须先正常退出，用户授权 QQ 应用及其数据目录后才能安装。助手可恢复原版入口。正常使用不需要重复打开助手。

Windows 安装器只安装 QQmanager，不修改 QQ。QQ 自动接入需兼容加载器，见 [插件说明](NATIVE-PLUGIN.md)。未完成 Windows QQ 实测时，推荐先用导入和目录监听。

## 构建

依赖 Node.js 24、Rust stable、Python 3.12（源码最低 3.9）；`npm ci` 安装锁定的 Tauri CLI，`pip install -r requirements-build.txt` 安装后端构建依赖。

执行 `python scripts/desktop/build_backend.py` 会把服务和网页冻结到 `build/backend`，再执行 `python scripts/desktop/smoke_backend.py` 验证真实打包程序。Mac 还需 `python scripts/build_mac_installer.py`（需要 Xcode Command Line Tools）。

- Mac：`npm run dist:mac` → `release/*.dmg`
- Windows：`npm run dist:win` → `release/*.exe`（当前用户 NSIS 一键安装）

必须在目标 OS / CPU 上打包 Python 后端；GitHub Actions 分别提供 macOS arm64、macOS x64、Windows x64 构建。Windows QQ 自动接入不属于安装包 smoke test 的覆盖范围。

## 发布与签名

首次公开版本采用试用版发布。当前构建没有 Apple Developer ID、公证或 Windows 商业签名，可能出现 Gatekeeper / SmartScreen 来源提示；用户自行核对仓库和 SHA-256，不能要求关闭系统保护。正式广泛分发前，维护者应添加平台证书并调整 Tauri 签名、公证配置。

构建只从明确的源码目录加入文件，不包括 `data`、`.venv`、QQ、容器会话或本机设置。发布前执行 `scripts/desktop/audit_release.py` 和自动化测试。依赖的许可证需随构建产物保留。Tauri 使用 MIT/Apache-2.0 许可，见上游项目。

## 调课与个人课表

启用消息分析并配置课表和校历后，后台会从已选群的调课事项生成待确认草稿。打开主页或课表中的橙色“待确认调课”，核对原日期、节次、新日期、节次、教室和原文，再确认更新。生效的课程显示蓝色“已调整”，点击可查看记录或撤销。

仅调整涉及的日期，其他周次和其他时段保留。时间重叠需额外勾选确认；无法唯一匹配、日期缺失或通知已更新时不能应用旧草稿。转发同一调课不会重复移动课程。多次调课从最新一次开始撤销。修改已经调课的课程原始星期、周次、节次或改变校历起点前，需先撤销相关调课。

模型接收已授权群的相关通知文字和校历日期、作息，用于解释相对日期和教学周；个人课程匹配与冲突检查在本机执行。识别本身不会修改课表。支持已有课程的日期、节次和教室移动；不完整的停课、补课或考试通知不会自动变成课表变更。

## 界面分工（0.4.0）

- 概览：今天、本周、本月切换，按日期集中查看事情；大数字展示待办、收集消息和重要消息。周视图为宽卡片列表，彩色点线区分类型。
- 课表：浏览完整一周；课程增删、停用、校历与作息放在“管理课程与校历”中。
- 事项：按分类检索整理后的事项；详情用概览、附件、原文三个标签分开显示。
- 文件、待办：各自检索和管理。原始记录、接入和设置放在导航下方。
- 页面支持窄屏布局；这不代表已提供手机服务或开放局域网。当前后端仍只监听本机回环地址。

Windows 首屏可以打开本机 QQ，在 QQ 的窗口完成登录，然后在 QQmanager 中填写同一 QQ 号。也可直接进入本地课表和资料库。要收集群消息，在已有兼容 LiteLoaderQQNT 的电脑上，从「设置 → 桌面应用」安装插件，重启 QQ 后选择收集的群。Windows 的启动和接入流程均无需 Docker；旧托管账号升级时会停用旧容器连接，保留账号、选群和历史资料。

Mac 仍可用手机 QQ 扫码绑定，托管扫码使用 Docker Desktop 或 OrbStack 运行登录组件。已绑定的桌面 QQ 插件用户可直接使用。部署边界见 [轻量化与移动端边界](LIGHTWEIGHT.md)。

## 0.4.0 轻量外壳与升级

外壳改为 Tauri 2，Mac 使用系统 WebKit，Windows 10/11 x64 使用 WebView2。Windows 安装器内含 WebView2 引导器，运行时缺少时需要联网安装。不内置 Chromium/Electron。Python 数据服务、QQ 插件、模型分析与原文数据库保持原有协议。

保留原桌面版数据目录：Mac 为 `~/Library/Application Support/QQmanager`，Windows 为 `%APPDATA%/QQmanager`。若本机已有 QQmanager 服务，则先验证身份并复用数据目录。升级前退出旧桌面程序；卸载旧外壳时不要删除应用数据。

Windows「设置 → 桌面应用」里的“安装 / 更新 QQ 消息插件”可选择已有 LiteLoaderQQNT 用户目录（包含 plugins 与 data），安装插件并写入配对配置。先在接入页保存 QQ 账号；不会自动安装加载器或更改 QQ 校验。加载器仍需对照用户 QQ 版本验证。

常用群筛选只列当前收集名单；已移除群的旧消息仍在“原始记录”的历史群筛选中。

Windows 构建另需 MSVC/C++ Build Tools，Mac 需 Xcode Command Line Tools。Windows CI 额外验证 NSIS 安装、WebView2 加载、后台启动、单实例及退出后的后端清理。

## 考试日期与消息覆盖

已启用模型时，后台会从授权群的考试事项及附件文字中整理科目、日期、时段、考场和适用班级，保留逐字原文依据。图片使用本机 OCR 坐标辅助对应表格行列，原图不发送。在“设置 → 学籍信息”保存班级后，日程会立即重新筛选已识别的考试。本地考试表中班级和时段明确的场次直接显示在对应日期，提醒可另行添加。近似 OCR 科目匹配会提示核对，明确其他班级的场次不进入个人安排。

考试候选显示在对应日期及近期考试区域，课表页也显示当周场次。所有自动提取日期均为待核对，不自动创建提醒或改动上课时间；点开后查看原图与证据，再添加提醒。通知、附件或校历更新后，旧候选失效并重新整理；原始消息保留。仅有教学周但缺少具体日期的通知仍留在关注事项中。

消息汇总按当前收集群、实际入库日期统计，重要消息按原始消息 ID 去重，再按事项组织；统计数量不同于合并后的事项数。不重要、尚未完成分析的消息也可在“查看全部”中翻页查看。

### 0.4.1 概览布局

日期、星期、教学周与时间切换集中在顶部。所有安排、近期考试和重要消息使用相同的单列行，颜色只用于类型圆点与标签。周视图省略无安排的空行，已经显示在安排中的事项不在重要消息区重复列出；完整消息仍可通过顶部统计或“全部消息”打开。完整调课日期在详情中保留。此次调整未增加运行依赖。
