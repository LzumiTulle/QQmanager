一、第一次在 Windows 上获取项目

安装 Git for Windows 和 Python 3.12。完成后，打开一个新的 PowerShell 窗口。
Git 下载：https://git-scm.com/downloads/win
Python 下载：https://www.python.org/downloads/windows/

在你想存放项目的文件夹中打开 PowerShell，逐行运行：

    git clone --branch main https://github.com/LzumiTulle/QQmanager.git
    cd QQmanager
    git status -sb

第一行只需执行一次。最后一条命令应显示分支 main。
以后在 Windows 上开发，就用编辑器打开这个 QQmanager 文件夹。

如果电脑上已经有这个仓库，直接在仓库文件夹打开 PowerShell。
先运行 git status 确认已有修改都已保存并提交，然后执行：

    git fetch origin
    git switch main
    git pull --ff-only

二、运行项目并查看修改

在 QQmanager 文件夹中运行：

    .\start-windows.cmd

首次启动会创建 Python 环境并安装依赖。保持终端打开，然后在浏览器访问：
    http://127.0.0.1:8765

按 Ctrl+C 可以停止本次服务。修改 Python 代码后，重新运行启动命令。
如果提示端口 8765 已被占用，先退出正在运行的 QQmanager，再启动开发版。

三、每次在 Mac 和 Windows 之间切换

刚合入仓库的功能可以从 main 获取。如果正在开发的修改还在其他分支，
先在原电脑运行 git branch --show-current 查看分支名，在另一台电脑运行
git fetch origin，再用 git switch 切到同名分支。

离开当前电脑前，在仓库文件夹中查看修改，把要同步的文件加入提交。
例如，这次只修改了 web/app.js，就运行以下命令；其他文件请换成实际路径。

    git status -sb
    git add -- web/app.js
    git diff --cached
    git commit -m "更新事项页面"
    git push

等推送成功后，在另一台电脑的同一分支运行：

    git pull --ff-only
    git log -1 --oneline

两台电脑最后一条提交的编号相同，就已同步到同一进度。
如果拉取时提示分支已分叉，保留两边的修改，先核对各自的提交再合并。
如果更新包含 requirements.txt 的变动，在 Windows 仓库中执行：

    .\.venv\Scripts\python.exe -m pip install -r requirements.txt

四、代码、个人数据和安装包

Git 同步已提交并推送的项目文件。群聊、待办、附件、模型密钥和 QQ 登录信息
保存在各自电脑上，请勿加入公开仓库。

只想使用桌面应用时，在本指南开头的「安装包」页面选择带有 Windows x64
安装器的版本，展开 Assets 并下载 .exe。安装包内置运行环境。

五、交接存档

2026-11-20　同一事项自动归并，课堂通知归入对应课次

  从使用者的角度，同一条群消息无论在 Mac 还是 Windows 上收到，打开「事项」
  和日程表都应看到相同的归属、最新要求和可追溯的原文。例：先通知编译原理
  实验做 C4，老师紧接着更正为 C4+C5，对应课次显示更正内容，「此前通知」
  可查最初的 C4。全量刷新再次处理历史消息时，也应得到同一结果。

  开发思路
  • 把识别放在共享 Python 服务。course_notices.py 按生效课表匹配课程和课次，
    包括调课、日期和实验场地。matter_matching.py 用课次、课程及作业次数、
    具名表单或重复原文提供归并依据。两端共用判定与数据，界面只呈现结果。
  • 对“更正：C4+C5”“这份作业改交……”这样的短句，只引用同一会话中
    30 分钟内同一发送者紧邻的上一条消息。中间插入无关消息或有多个可能
    对象时，保留独立处理的机会。确定的本地匹配在关闭模型时也能生效。
  • 保护人的决定。重复转发沿用已确认状态，有实质变化时提示复核。核对已有
    待办和计划仍然关联，人工拆分、合并的结果在全量刷新后仍然有效。

  双端验收
  1. 用相同的合成课表和群消息，在两端依次验证新消息、历史导入、全量刷新。
     同一次实验的 C4 与更正应归在一起；下一周的课次、同一课程的第四次和
     第五次作业应能分别打开。再手动拆开一项、刷新，核对原文、状态和计划。
  2. 使用同一份数据比较结果，再按平台检验实际操作。Mac 用 ⌘K、触控板和
     菜单栏入口；Windows 用 Ctrl+K、鼠标和系统托盘。两端均可用按钮完成
     合并。检验详情滚动、键盘焦点和长中文标题，尤其注意 Windows 高 DPI
     或放大字号时按钮能否完整显示。文件选择、通知沿用各自系统控件。
  3. 共享回归见 tests/test_matter_matching.py、tests/test_schedule.py 和
     tests/schedule_view.test.cjs。桌面构建结果见文首链接。交接时分别记录
     自动测试、安装启动与真机交互的验证范围，未验证项写清平台和场景。

  本次在 macOS 对 main 候选代码运行 162 项 Python 测试（1 项原生 OCR 默认跳过），
  以及 29 项 Node 测试，均无失败。两端安装包构建与启动见对应提交的 Actions
  记录。不同缩放下的鼠标、触控板和键盘操作仍需真机复核。

  Windows 维护者与 macOS 维护者都要更新本文件。变更识别规则、操作入口、
  平台行为或验收方法时，在同一个提交或 PR 补上日期、设计依据、平台差异和
  验证结果。分支独有的功能标出分支名；合入 main 时一并更新本记录。
  Windows 专用分支持续开发时，先提交本机改动，再执行 git fetch origin 和
  git merge origin/main，复查共享场景后推送。交接始终沿用文首固定地址。

Windows 本地接入适配（开发分支 codex/windows-native-local）
  源码  https://github.com/LzumiTulle/QQmanager/tree/codex/windows-native-local
  本地课表、资料库和待办可以直接使用。需要连接 QQ 时，先在 Windows QQ 客户端
  完成登录。打开 QQmanager 登录页或「设置 → 账号与收集」时，应用会在 Windows
  文档目录的 Tencent Files 中检查 QQ 客户端正在使用的账号。只检测到一个时自动
  填入；同时检测到多个时由你选择。核对后点「保存账号并继续」。如使用自定义
  数据目录或暂未识别到，可以重新识别或手动输入。历史账号目录不会单独作为
  已登录的依据。识别只查询文件占用，不读取聊天内容，也不会开启消息收集。
  首次启动、账号接入、重连和升级均不需要 Docker。登录二维码由 QQ 客户端显示。
  已经在 QQ 中启用兼容 LiteLoaderQQNT 的用户，可以在保存账号时勾选「同时安装
  或更新 QQ 消息插件」，也可以从「设置 → 桌面应用」单独安装。助手优先使用
  LITELOADERQQNT_PROFILE，其次用上次安装成功的位置，再检查文档和 AppData
  漫游目录中的 LiteLoaderQQNT。未能唯一定位时可手选已有目录，或取消安装。
  助手复制随包插件并完成本机配对。替换旧版时备份原插件和配置，相同版本
  和配置可重复安装。正常退出并重新打开 QQ 后，在 QQmanager 选择要收集的群。
  全新 QQ 需要已有的兼容加载器才能加载插件。没有插件也可以手动导入记录。
  旧托管账号升级后保留本机账号、选群和已归档内容，停用旧容器连接。
  Windows 的深色窗口、放大的中文字号和桌面设置也在同一分支。下方 0.4.2
  发布快照早于此次适配；验证本次改动请使用上面的开发分支。
